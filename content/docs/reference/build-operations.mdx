Generated from the shared Build registry. Call these operations with `POST /api/build/OPERATION_NAME`, the MCP tool of the same name, or a compatible CLI's `datool build call OPERATION_NAME --input @input.json`. Use `build_describe_operations` (or `datool build tools`) on the target server for complete current input and available output schemas. Build must be enabled and the credential must hold every listed scope. Observe operations use a [separate endpoint and catalog](/docs/reference/operations).

Use [agent configuration and drives](/docs/guides/agents), [integrations](/docs/guides/integrations), [scheduled tasks](/docs/guides/scheduled-tasks), and [React SDK](/docs/guides/react-sdk) for workflows and examples. The tool `build_get_authoring_guide` returns validated examples and semantic constraints for these topics.

Successful REST results are wrapped in `{ "data": ... }`; MCP returns the same envelope in structuredContent. When outputSchema is advertised it describes that envelope. Required retry keys can be supplied as `idempotencyKey` or `requestKey` in tool input; REST also accepts the Idempotency-Key header. Use the current expectedRevision for revision-protected edits. Read a saved state before retrying an uncertain mutation.

## build_sdk_files

List, read, write, create directories or delete files in an application's isolated drive. File transfers are bounded to 256 KiB and directory listings to 500 entries. Read/write content uses base64; the SDK encodes/decodes it. Paths are relative to the drive; traversal and symlinks are rejected. Deletes never recurse. Creating a drive records its agent and workspace for Sandbox; no chat session is required.

Required scopes: `build:write`, `build:run`. Idempotency key: **none**. Expected revision: **none**.

**Request fields**

| Field | Type | Required |
| --- | --- | --- |
| `connectionId` | string | Yes |
| `userId` | string | Yes |
| `drive` | string | No |
| `workspaceName` | string | No |
| `request` | object | Yes |

**Result**

Type: **object**.

## build_sdk_tasks

Manage proactive tasks within a server-authenticated SDK conversation. Create through this operation, not build_create_scheduled_task, for per-user tasks. Tasks and queued runs retain the original connection, user scope, drive and conversation, including dashboard-triggered runs. Changed or missing bindings fail closed. Updates cannot rebind a task. Current file contents are read at execution. Supply idempotencyKey and current expectedRevision when required by the request action.

Required scopes: `build:read`, `build:write`, `build:run`. Idempotency key: **required**. Expected revision: **none**.
