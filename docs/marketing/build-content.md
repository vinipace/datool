## Article about evaluating a customer service agent

### How to test an AI agent with questions from your store

An AI agent demo is easier to judge when it uses a question your customers already ask. Pick one from your inbox and bring the product page, help article or policy that should support the answer.

For a store, “Will this fit?” is a useful starting point. The agent needs to find the relevant measurements and explain them clearly. A question about delivery adds another requirement: access to current order data. A request for an exception tests whether the agent can bring in a person.

#### Start with the answer you expect

Choose a few cases from recent customer conversations. Include a straightforward question and a request your team would need to handle. Write down the facts the agent should use and the point where it should stop or hand off.

For a product question, that might mean using the listed dimensions, asking for a missing measurement and explaining the return policy. For an order question, it might mean checking the connected store after verifying the customer's access. A customer typing an order number does not by itself authorize access to private order details.

#### Check where the information comes from

Ask to see the source behind the reply. Product descriptions and policies can come from connected knowledge. Current stock, prices and order status need a suitable store connection or API.

Check how that information is refreshed. A copied product page and a live stock lookup serve different purposes. Ask the agent about an item that is unavailable and an order lookup that fails. Those cases help you decide whether its fallback is useful.

#### Follow the handoff

Give the agent a request that needs an exception, then inspect what your team would receive. Look for the conversation history, collected details and steps already tried. Check how a person takes over and sends a reply.

Agree on which requests belong with your team before launch. Your business may want a person to approve refunds, discuss a complaint or handle an unusual delivery request. Configure those boundaries and test them.

#### Keep the questions for the next change

Save the cases and their expected behavior. When you change a policy, instruction or action, run them again and compare the answers. Check individual failures as well as the overall result.

After launch, review customer conversations and add useful cases. A repeated question that the agent struggles with is a practical place to focus the next improvement.
